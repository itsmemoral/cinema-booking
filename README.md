# Cinema Booking

![CI](https://github.com/itsmemoral/cinema-booking/actions/workflows/ci.yml/badge.svg)

Сервис бронирования мест в кинотеатре. Пет-проект: разработка backend-приложения
и покрытие его автотестами.

## Стек

**Приложение:** Java 21, Spring Boot, Spring Data JPA, PostgreSQL 16, Flyway
**Тесты:** JUnit 5, Mockito, AssertJ, Testcontainers, Allure
**Инфраструктура:** Maven, Docker Compose, GitHub Actions

## Запуск

```bash
docker compose up -d
./mvnw spring-boot:run
```

Приложение поднимается на `http://localhost:8080`.

## API

| Метод | Путь         | Описание                    |
|-------|--------------|-----------------------------|
| POST  | `/api/halls` | Создать зал с местами       |
| GET   | `/api/halls` | Получить список залов       |

Ошибки возвращаются в формате RFC 7807 (`ProblemDetail`): 409 при попытке
создать зал с уже занятым названием, 400 с перечнем полей при невалидных данных.

## Тесты

```bash
./mvnw verify
```

Два уровня:

- **Юнит-тесты** (`*Test`, Surefire) — логика сервисов в изоляции, репозитории
  подменяются моками. Базы данных не требуют.
- **Интеграционные** (`*IT`, Failsafe) — приложение поднимается целиком,
  запросы идут по HTTP. PostgreSQL поднимается в контейнере через Testcontainers,
  миграции Flyway применяются с нуля при каждом прогоне.

Тесты самодостаточны: локально запущенная база им не нужна, поэтому они
одинаково работают на машине разработчика и в CI.

### Отчёт Allure

```bash
./mvnw verify
./mvnw allure:serve
```

## CI

При каждом пуше в `main` GitHub Actions собирает проект, прогоняет все тесты
и сохраняет результаты Allure как артефакт сборки.
